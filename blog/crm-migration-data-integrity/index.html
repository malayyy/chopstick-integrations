FIELD NOTE

A CRM migration is a data project before it is a software project

A reliable migration protects relationships, history and business rules — not just rows and columns.

CHOPSTICK INTEGRATIONS · 6 min read · 7 NOVEMBER 2026

Importing contacts into a new CRM is the easy part. The difficult work is preserving meaning: which deal belongs to which account, who owns the next action, how custom fields map and which workflows should run after cutover.

Inventory before moving

List modules, record counts, field types, relationships, attachments, activities, users, permissions, workflows, reports and integrations. Identify fields that look similar but carry different business meanings.

Map and normalize

Create a mapping for every critical field, including transformation and validation rules. Normalize phone numbers, email addresses, picklist values and dates. Define duplicate matching and conflict resolution before the migration starts.

Preserve relationships and history

Contacts, accounts, deals, notes, tasks, calls and attachments depend on IDs and lookup relationships. Plan migration order and maintain a source-to-target ID map. Decide which historical activities must be retained and linked.

Test the real operating scenarios

  • Run sample migrations with edge cases.
  • Compare source and destination counts by module.
  • Validate relationships, attachments, ownership and permissions.
  • Test critical workflows with automation safely isolated.
  • Have users verify real scenarios before cutover.
A migration is complete when the team can continue work with trusted records, working processes and a reconciled audit trail — not when the import bar reaches 100%.

Plan cutover and rollback

Set a freeze window, final delta migration, reconciliation checklist, communication plan and rollback criteria. Keep an auditable record of what moved, what failed and what was corrected.
